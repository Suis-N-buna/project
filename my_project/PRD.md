# PRD: 첫 개인 포트폴리오 웹사이트

## 1. 프로젝트 정의

HTML과 CSS만으로 만드는, 1학년 개발자의 자기소개와 학습 결과물을 보여주는 반응형 개인 포트폴리오 웹사이트.

- **제작자:** HTML과 CSS의 기초를 배우고 첫 포트폴리오를 만드는 대학 1학년 개발자.
- **주요 방문자:** 함께 프로젝트를 할 신입 부원을 찾는 교내 개발 동아리 운영진과 조별 과제 팀원.
- **해결할 문제:** 자기소개, 과제 결과물, 연락처가 흩어져 있어 협업을 제안받을 때마다 자료를 따로 정리해서 보내야 한다.
- **목표:** 하나의 페이지에서 관심 분야, 프로젝트 경험, 연락 방법을 확인할 수 있게 한다.
- **가정:** 이름, 실제 프로젝트, 이메일은 아직 제공되지 않았다. 제작 중에는 예시임을 표시한 내용을 사용하고 공개 전에 실제 정보로 교체한다.

## 2. 핵심 기능 3개

| 기능 | 사용자 행동과 결과 | 필수 콘텐츠 |
|---|---|---|
| 자기소개 확인 | 상단 ABOUT을 누르면 자기소개 영역으로 이동한다. | 이름, 한 줄 소개, 관심 분야, 학습 중인 기술 |
| 프로젝트 확인 | PROJECTS를 누르면 프로젝트 목록으로 이동하고 각 작업의 목적과 배운 점을 읽을 수 있다. | 프로젝트명, 설명, 사용 기술, 담당한 부분, 배운 점 |
| 연락하기 | CONTACT를 누르면 연락처로 이동하고 이메일 링크를 누르면 기기에 설정된 이메일 앱으로 작성 화면을 연다. | 화면에 표시되는 이메일 주소, 이메일 링크 |

이메일 앱이 설정되지 않은 환경에서도 주소를 직접 선택하고 복사할 수 있도록 이메일을 텍스트로 표시한다. 실제 이메일 전송은 방문자의 이메일 앱에서 이루어진다.

## 3. 범위와 산출물

### 필수 범위

- 단일 페이지에 ABOUT, PROJECTS, CONTACT 세 영역을 배치한다.
- 상단 메뉴는 정확히 `ABOUT`, `PROJECTS`, `CONTACT`로 표시한다.
- `<header>`에 푸른 계열 배경색을 적용한다.
- HTML5 시맨틱 구조와 키보드 접근성을 고려한다.
- 데스크톱, 태블릿, 모바일에 대응한다.
- 실행 파일은 `index.html`, `style.css` 두 개로 구성한다.
- 외부 라이브러리, JavaScript, 빌드 과정 없이 브라우저에서 열 수 있어야 한다.

### 이번 버전에서 제외

로그인, 관리자 페이지, 데이터베이스, 문의 전송 서버, 프로젝트 검색·필터, 모바일 햄버거 메뉴, 자동 테마 전환은 구현하지 않는다. 작은 화면에서도 세 메뉴를 그대로 노출한다.

### 파일 구성

```text
my_project/
├── index.html    # 콘텐츠, 시맨틱 구조, 링크
└── style.css     # 색상, 글꼴, 배치, 반응형, 포커스 스타일
```

이 PRD와 기존 디자인 문서는 기획 참고 자료이며 웹사이트 실행에 필요한 파일은 위 두 개다. `index.html`의 `<head>`에 `<link rel="stylesheet" href="style.css">`를 작성한다. 인라인 스타일과 `<style>` 태그 대신 `style.css`에서 스타일을 관리한다.

## 4. 페이지 구성과 콘텐츠

| 순서 | 영역 | 내용과 동작 |
|---|---|---|
| 1 | 건너뛰기 링크 | 첫 키보드 포커스에서 보이는 ‘본문 바로가기’. `#main-content`로 연결 |
| 2 | header | 포트폴리오 이름과 세 메뉴. 푸른색 배경, 흰색 글자 |
| 3 | ABOUT | 대표 제목, 이름, 2~3문장 소개, HTML·CSS 등 학습 기술 목록 |
| 4 | PROJECTS | 프로젝트 카드 3개를 기준으로 구성. 실제 프로젝트 수에 맞게 조절 가능 |
| 5 | CONTACT | 짧은 협업 안내와 이메일 주소. 제공된 경우에만 GitHub 링크 추가 |
| 6 | footer | 제작자 이름과 간단한 저작권 문구 |

프로젝트 카드에는 제목, 해결하려던 문제, 구현 내용, 사용 기술, 본인 역할, 배운 점을 짧게 작성한다. 저장소나 결과물 주소가 있는 경우에만 링크를 제공한다. 준비 중인 작업은 ‘준비 중’으로 표시하고 빈 링크나 `href="#"`로 연결하지 않는다. 예시 프로젝트나 예시 성과를 실제 경험처럼 표현하지 않는다.

## 5. 기술적 구현 방향

### HTML

- 문서 시작에 `<!DOCTYPE html>`을 선언하고 `<html lang="ko">`를 사용한다.
- `<meta charset="UTF-8">`, viewport 메타 태그, 의미 있는 페이지 제목과 설명을 작성한다.
- `<header>`, `<nav aria-label="주요 메뉴">`, `<main id="main-content">`, `<section>`, `<article>`, `<footer>`로 구조를 만든다.
- 각 섹션의 ID를 `about`, `projects`, `contact`로 지정하고 메뉴의 `href`를 각각 `#about`, `#projects`, `#contact`로 연결한다.
- 대표 제목은 `h1` 하나, 주요 섹션 제목은 `h2`, 프로젝트 제목은 `h3`로 구성한다.
- 각 프로젝트는 독립적인 `<article>`, 학습 기술과 메뉴는 목록 태그로 표현한다.
- 페이지 이동과 이메일 열기는 `<a>`를 사용한다. 동작이 없는 버튼은 만들지 않는다.
- 본문 바로가기의 대상에는 필요 시 `tabindex="-1"`을 적용해 포커스 이동을 지원한다.

### CSS

- 모바일 화면을 기본으로 작성한 뒤 `min-width` 미디어 쿼리로 확장한다.
- 공통 색상, 여백, 최대 콘텐츠 너비는 CSS 사용자 정의 속성으로 관리한다.
- 전체에 `box-sizing: border-box`를 적용한다.
- 헤더 메뉴에는 Flexbox, 프로젝트 목록에는 CSS Grid를 사용한다.
- 콘텐츠 최대 너비는 `1100px`, 좌우 여백은 모바일 `20px`, 큰 화면 `32px`를 기본으로 한다.
- 긴 이메일과 URL에는 `overflow-wrap: anywhere`를 적용해 가로 넘침을 방지한다.
- 고정 높이 대신 콘텐츠에 따라 높이가 늘어나도록 구성한다.
- 헤더는 일반 문서 흐름에 둬 섹션 제목이나 키보드 포커스를 가리지 않게 한다.
- 시스템 글꼴을 사용해 별도 폰트 다운로드 없이 표시한다.

## 6. 디자인과 반응형 규칙

기존 `DESIGN.md`, `DESIGN-apple.md`에서 여백 중심 구성, 명확한 제목 위계, 단순한 표면 구분을 참고한다. 브랜드 전용 글꼴과 차량·제품 이미지는 가져오지 않으며, 사용자가 요청한 푸른색 헤더를 우선한다.

| 항목 | 구현 기준 |
|---|---|
| 헤더 | 배경 `#123B70`, 글자 `#FFFFFF` |
| 본문 | 배경 `#FFFFFF`, 기본 글자 `#172B4D` |
| 보조 영역 | 배경 `#F3F6FA`, 보조 글자 `#475569` |
| 링크 | `#174EA6`, 본문 링크는 밑줄로 구분 |
| 글꼴 | `system-ui, -apple-system, "Segoe UI", "Malgun Gothic", sans-serif` |
| 본문 크기 | 기본 `16px`, 줄 간격 `1.6` |
| 대표 제목 | `clamp(2rem, 5vw, 3.5rem)`으로 조절 |
| 카드 | 얇은 테두리, 약 `12px` 모서리, 충분한 내부 여백 |

| 화면 너비 | 레이아웃 |
|---|---|
| 768px 미만 | 헤더 이름과 메뉴를 위아래 배치, 프로젝트 1열 |
| 768px 이상 1024px 미만 | 이름과 메뉴를 가로 배치, 프로젝트 2열 |
| 1024px 이상 | 가운데 정렬한 최대 너비 컨테이너, 프로젝트 3열 |

320px에서도 세 메뉴가 읽히도록 간격과 줄바꿈을 허용한다. 메뉴의 클릭·터치 영역은 최소 `44 × 44px`를 목표로 한다. 장식 애니메이션은 필수가 아니며, 부드러운 스크롤을 추가한다면 `prefers-reduced-motion: reduce`에서는 기본 스크롤로 전환한다.

## 7. 접근성 요구사항

- Tab 키만으로 건너뛰기 링크, 메뉴, 프로젝트 링크, 이메일 링크에 순서대로 접근할 수 있다.
- `:focus-visible`에 명확한 외곽선을 제공하고 기본 포커스 표시를 무조건 제거하지 않는다. 흰 배경과 푸른 헤더 각각에서 식별 가능한 색상을 사용한다.
- 일반 본문은 명암 대비 `4.5:1` 이상을 목표로 확인한다.
- 마우스를 올렸을 때만 정보를 제공하지 않는다.
- 링크 텍스트는 ‘더 보기’ 대신 ‘프로젝트명 저장소 보기’처럼 목적을 설명한다.
- 초기 버전은 텍스트와 CSS로 구성해 이미지 없이도 완성한다. 추후 이미지를 추가하면 의미 있는 이미지는 대체 텍스트, 장식 이미지는 빈 `alt`를 사용한다.
- 브라우저 확대 시 콘텐츠가 겹치거나 잘리지 않아야 한다.

## 8. 구현 순서

1. 이름, 소개, 프로젝트 정보, 연락처를 준비하고 미제공 정보는 예시로 표시한다.
2. `index.html`에 시맨틱 구조와 실제 콘텐츠, 섹션 이동 링크를 작성한다.
3. `style.css`를 연결하고 푸른 헤더와 모바일 기본 레이아웃을 구현한다.
4. 태블릿·데스크톱 미디어 쿼리와 프로젝트 Grid를 추가한다.
5. 건너뛰기 링크, 포커스 표시, 긴 문자열 처리를 보완한다.
6. 아래 완료 기준을 수동 검증하고 실제 정보로 교체한다.

## 9. 완료 기준 및 검증

| 검증 항목 | 통과 기준 |
|---|---|
| 파일 연결 | `index.html`을 직접 열었을 때 `style.css`가 적용되며 푸른 헤더가 보임 |
| 메뉴 | ABOUT, PROJECTS, CONTACT가 모두 표시되고 각각 올바른 섹션으로 이동 |
| 콘텐츠 | 자기소개, 프로젝트 정보, 화면에서 읽을 수 있는 이메일 주소가 존재 |
| 반응형 | 320, 375, 768, 1024, 1440px에서 가로 스크롤·겹침·잘림이 없음 |
| 경계 너비 | 767/768px, 1023/1024px에서 메뉴와 카드가 정상 배치됨 |
| 키보드 | Tab 이동과 Enter 활성화가 가능하고 모든 링크의 포커스가 보임 |
| 본문 이동 | 본문 바로가기를 실행하면 헤더를 건너뛰고 본문에 접근 가능 |
| 확대 | 브라우저 200% 확대 상태에서 글자와 링크가 겹치거나 잘리지 않음 |
| 링크 | 빈 링크가 없고 프로젝트 링크가 의도한 대상으로 연결됨 |
| 이메일 | `mailto:` 주소와 화면의 주소가 일치하며 이메일 앱이 설정된 환경에서 작성 화면이 열림 |
| 구조 | 중복 ID 없이 h1→h2→h3 순서와 HTML5 시맨틱 구조를 유지 |
| 대비 | 본문·링크·헤더 글자와 각 배경의 명암 대비를 확인 |
| 브라우저 | 사용 가능한 Chrome 또는 Edge와 Firefox에서 주요 기능 및 배치를 확인 |
| 공개 준비 | 예시 이름·연락처·프로젝트를 실제 정보로 바꾸거나 준비 중 상태로 명시 |

검증 결과는 실제 수행한 항목만 기록한다. 이 문서는 구현 계획이며, HTML·CSS 구현과 브라우저 검증 완료를 의미하지 않는다.
